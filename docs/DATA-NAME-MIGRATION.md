# GardenBoot → Sakura 数据名迁移方案（未实现）

**时机**：独立稳定版升级，经两端故障注入与旧版升级验收后启用。P-017 不改迁移代码、路径、偏好域、bundle ID 或登录项；迁移与设置格式升级分开做。测试根目录不得触及真实数据。

| 平台 | 旧位置 → 拟用位置 |
| --- | --- |
| macOS 数据 | `~/Library/Application Support/GardenBoot/` → 同级 `Sakura/` |
| macOS 缓存 | `~/Library/Caches/GardenBoot/Thumbnails/` → `~/Library/Caches/Sakura/Thumbnails/`（重建，不搬开发构建缓存） |
| macOS 偏好 | 首阶段保留 UserDefaults 域 `local.gardenboot.GardenBoot`；将来换域另做事务，禁止直接移动 plist |
| Windows | `%LOCALAPPDATA%\GardenBoot\` → 同级 `Sakura\`（含 `thumbs`，可重建） |

**检测**：初始化日志/监听器之前取得跨版本互斥锁。只有旧目录则迁移；只有已完成的新目录则使用新根；两者皆无则新建；两者并存且无有效事务记录时停止自动迁移、保留两边，让用户选择，禁止按时间猜测或覆盖合并。不可读/损坏、未来格式、链接逃逸均停止，保留完整旧数据并提示错误。

**原子提交**：保留旧根，复制到目标同卷 `.Sakura-migrate-<id>`；校验文件大小/散列、磁盘空间、设置与包引用。暂存落盘后原子重命名为 Sakura，再原子写入含版本、源/目标、清单与阶段的完成标记。目录与偏好不能一次原子提交，所以先保留偏好域。崩溃重启按事务阶段恢复；未完成的新根不可作为权威数据。跨卷先完整复制校验，再做目标卷内重命名，不宣称跨卷移动原子化。

**保留与回滚**：保留 Packs、参数/方案、播放/轮换记录、Windows settings.json、Mac 当前选择/精选已安装/引导/更新偏好；包 ID 不变，仅重写指向旧根的内部引用，不改外部媒体和目标应用路径。首次成功启动且可写前可回退旧根；之后备份只读保留至用户接受和保留期结束。新根已有写入时禁止静默回滚到旧副本：先退出各版本、备份新根，再显式恢复到旧根并校验。降级同样走此流程，发布说明须说明双版本不能并行各写一份。

**测试**：两端空安装、旧版全量数据、当前/每应用动画/方案与精选删除状态保留；旧新并存、重启幂等、跨版本锁；逐阶段断电/强退、磁盘满/拒绝访问、复制/校验/重命名/标记失败；Unicode/长路径、链接逃逸、损坏/未来设置；缓存重建、旧文件完整、写新数据后显式回滚、`--test-root` 隔离。最后由用户在可恢复备份的机器按[验收说明](VERIFICATION.md)实测。
