# 开场无黑屏与首帧时间（P-006）

问题（2026-11-14 Windows 真实日志）：叠加窗口在 `player-show` 时立即以黑底出现，等全部三段视频打开后才开始播放，用户每次先看到 1.4–2.6 秒纯黑窗口。

## 规则

1. **首帧前不可见**：叠加窗口可以提前创建和定位，但在第一段视频的第一帧真正绘制出来之前保持完全透明（不接收点击、不显示提示）。首帧就绪后 0.12 秒淡入。`player-show` 日志改为在“开始淡入”时写，并保留 `location=` 与 `frame=`。
2. **按段就绪**：第一段（intro，或没有 intro 时的 loop/唯一视频）就绪即开始播放，不等其余段。其余段在后台继续准备；状态机要求播放某段而它尚未就绪时，保持当前画面（不黑屏），就绪后立即切换；任一段在准备上限内失败或超时，按原有失败流程处理。
3. **热备**：启动器空闲时，为“下一次最可能播放的包”预先准备第一段，并停在第 0 帧：固定轮换时是当前包；随机轮换时是轮换候选中下标 0 之外不做预测，只热备当前包。当前包、动画包内容或个人设置改变时重建热备。热备只占用一个解码器；它被本次播放使用后，播放结束时为下次重新准备。系统休眠唤醒后重新准备一次。
4. **跳过与超时**：首帧前按 Esc、目标退出、切走等仍按原状态机处理；若因此结束，窗口从未可见，不闪现。首帧前的时间仍计入最长等待。
5. **预览**同样遵守 1、2，可使用热备。

## 日志与指标

- `first-frame age=<秒> warm=<true|false> segment=<intro|loop|outro|video>`：从 `launch-detected`（预览为 `preview-requested`）到首帧绘制的秒数，3 位小数。
- 目标（开发电脑上测）：热备 ≤ 0.35 秒；冷启动 ≤ 1.5 秒。超过时记录，不以放宽等待规则换取通过。
- 检查脚本断言：`first-frame` 出现在 `player-show` 之前或同一刻；`player-show` 之前没有任何可见窗口（Windows 以窗口 `Opacity`/分层透明度，macOS 以 `alphaValue` 记录 `overlay-alpha=` 诊断行判断）。

本规则只涉及应用层，不改变 `playback.json` 状态机。
