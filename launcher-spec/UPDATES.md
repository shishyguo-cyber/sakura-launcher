# 检查与安装更新（P-014 / P-019）

用户 2026-11-16 要求：已下载旧版的用户要能知道有新版本。用户确认采用推荐方案：**自动检查只提醒、不自动安装**，自动检查默认打开、每周一次，可关闭。

## 1. 行为

- 菜单栏/托盘菜单新增 **检查更新…**（立即检查并给出结果）和可勾选的 **自动检查更新**（默认打开）。
- 自动检查：启动 60 秒后，以及运行期间每 6 小时判断一次；距离上次成功检查超过 7 天才真正联网。
- 发现新版本后，菜单显示 **有新版本 <版本号> · 更新…**。用户点击才下载当前平台包，验签后替换并重启；下载可取消，失败保留或恢复旧版，保留“在 GitHub 查看”入口。安全协议、安装与回退见 [SIGNED-UPDATES.md](SIGNED-UPDATES.md)。结果保存在本机，下次启动不联网也能显示，直到用户换成该版本或更高版本。
- 手动检查：已是最新时提示“已是最新版本（<当前版本>）”；有新版本时打开概览供用户决定是否更新；失败时提示“暂时无法检查更新，请稍后再试”。
- 检查操作本身不下载或安装；仅明确点击“更新”后才开始安装流程。preview.7 及更早版本仍只有手动更新入口，需手动升级一次。

### 概览中的“版本与更新”

设置默认打开的概览页在播放状态下方显示当前版本、检查按钮和自动检查开关；原菜单入口保留，两处共享同一运行状态和偏好。开关立即生效，不保存动画参数草稿。手动检查的结果直接显示在概览内，检查中禁用重复点击，失败可重试；发现新版时显示“更新”和“在 GitHub 查看”，下载期间显示进度及“取消下载”。打开概览和刷新界面不会额外发起请求，独立离屏渲染禁用操作并标明预览。

## 2. 联网与隐私

- 检查只请求 `https://api.github.com/repos/shishyguo-cyber/sakura-launcher/releases?per_page=20`，HTTPS，10 秒超时，`User-Agent: Sakura/<当前版本>`。不附带账号、设备标识、设置或使用数据；GitHub 能看到请求方 IP，这是任何网络请求都会有的。
- 点击“更新”才请求固定仓库的 HTTPS Release ZIP 和签名，可能重定向到 GitHub 官方 release-assets 主机；不附带个人数据。
- 关闭“自动检查更新”后不再自动联网；手动“检查更新…”仍可用。
- 独立测试目录（`--test-root`）中不联网：自动检查默认关闭，只能用 `--test-update-feed <本地 JSON 文件>` 提供发布列表。

## 3. 版本规则（`UpdateRules`，两端一致，共享用例 `conformance/updates.json`）

- 当前版本：macOS 取 Info.plist 的 `SakuraReleaseVersion`，Windows 取程序集的 InformationalVersion（去掉 `+` 之后的部分）；都等于发布标签去掉开头的 `v`，例如 `0.2.0-preview.5`。
- `compare(a, b)`：按语义化版本比较。先比 `主.次.修订` 数字；相同时没有预发布后缀的更大；预发布后缀按 `.` 分段逐段比较，纯数字段按数值、其余按字符，数字段小于文字段，前面都相同时段数多的更大。版本号前的 `v` 忽略；无法解析的版本视为无效。
- `newest(releases, current)`：在发布列表中忽略草稿和无法解析的标签；当前版本是预发布时预发布版本也参与，当前版本是正式版时只看正式版；返回比当前更新的最高版本（版本号与网页地址），没有则为空。
- `isDue(lastCheckAt, now)`：从未检查过，或距离上次成功检查 ≥ 7 天（604800 秒）；时钟回拨（now < lastCheckAt）也视为到期。

## 4. 日志

`update-check source=auto|manual result=newer|current|failed latest=<版本|none>`；失败时只记录错误类别，不记录响应内容。
